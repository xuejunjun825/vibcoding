## 1 观感与视觉意图（实现前必读，先于信息架构）

### 1.1 一句话：尺、纸、管、表、章

五个域各有一种器物隐喻，所有取舍由此派生：

- **甘特 = 尺**：一条真正的时间尺。刻度必须诚实、可读，条 = 承诺（实心），浅带 = 事实（实际）；拖拽要像移动一件有重量的物件（跟手、落位、留痕），不像刷一下页面。
- **Wiki = 纸**：阅读态是一张安静的纸（700px 行宽），导航与工具栏退到两侧；编辑态是一张工作台（编辑 + 预览并置），不把纸做成后台表单。
- **价值流 = 管**：七个等宽列就是管道的剖面，每列一个读数；瓶颈用**顶部 2px 主色 + 文字**标出，不靠整列染色。
- **CCode = 表**：规则是「期望」，核验是「实际」，一张对照表把两者并排；绿色**只在 MATCH 时**出现。
- **CTest = 章 + 台账**：用例评审是一枚版本章（v3 通过 / v2 已过期），执行器是一台设备台账（指示灯 + 最近上报时间）。

语义色纪律 `[沿用]`：绿=服务端判定通过/已同步；红=失败/阻断/逾期；黄=需要人判断（未核验、临期、样本不足）；灰=未配置/无数据/不适用。**未核验永远不是绿色；无数据永远不是 0。**

### 1.4 动效、加载、空态与错误态

**甘特改期（本设计最关键的动效链）**
1. 拖拽：条跟手 0ms；浮动日期 chip 固定在条上方 8px：`03-04 → 03-11 · 8 天`；超出当前可见区时自动横向滚动（12px/帧边界触发）。
2. 松手：条落到目标位，**透明度 55% + 1px 虚线主色外框**，chip 变「保存中…」——这是「待确认」，不是成功。
3. 成功（服务端返回新 `version` 与 `auditId`）：透明度 1，条底闪 `#E8F7EC` 600ms 渐隐；顶部出现 32px 常驻条 1.2s：`已保存 · 已写入审计 GANTT_RESCHEDULE`。
4. 超父窗口 409：条 160ms 回到原位，打开 640px 确认弹窗（父窗口 / 超出天数 / 一次性确认码倒计时 / 「仅本条不顺延」）；确认后重提，走第 2–3 步。
5. 版本冲突 409：条回原位，行内出现 40px 黄条：`这行刚被 张三 修改（v7）` + [刷新并重试] [放弃]；**不静默刷新丢操作**。
6. 网络超时/5xx：条回原位 + 红条 `结果未知，请刷新后确认`；禁止显示成功。

**其他动效**
- 视图/缩放切换：时间轴与条**同帧替换**（无过渡动画），避免条「飞过去」造成读错；只在切换后 120ms 内淡入网格线。
- 价值流筛选变化：列内容 opacity 0.6→1（120ms），**数字不滚动、不位移**；列宽不变。
- Wiki 编辑保存：顶部版本 chip 数字直接替换；无变更时 `已保存 · 内容未变化，未生成新版本`（info 条，非 toast 成功）。
- Wiki 回滚：确认后抽屉关闭，正文替换 + 顶部 `已生成 v13（基于 v5）`；版本列表滚动到 v13。
- 评论「加载更多」：保留旧列表，底部 2px 进度条；新行一次性出现，不做逐条动画。
- 抽屉 240ms 从右滑入（`translateX(16px)→0` + opacity），关闭 160ms；`prefers-reduced-motion` 下只保留显隐。

**加载（骨架按最终尺寸，避免跳动）**
- 甘特：左树 8 行 ×40 + 时间轴网格 + 6 条灰条（`#F2F3F5`，圆角 4）。
- Wiki：树 10 行 ×32；正文 6 行段落块（宽 100/92/96/70%）；右栏 TOC 4 行。
- 价值流：KPI 条 1 块 + 7 列（每列 44 + 72 + 3×56）。
- 规则表 6 行 ×48；MR 评论 5 行 ×56；用例评审 3 行 ×64；执行器 6 行 ×56。
- 翻页/筛选保留旧数据 + 顶部 2px 进度条。

**空态（必须区分「还没有」「未配置」「筛选无结果」「无权限」）**
- 甘特：`当前视图没有可排期的条目` + [切换视图]；>300 折叠：顶部条 `已显示 300 条（共 412），其余按版本/迭代折叠` + [展开更多]。
- Wiki 空间空：`还没有页面` + [新建页面]；搜索空：`没有匹配的页面（仅搜索你有权限的空间）`；回收站空：`回收站是空的`；已删除页：正文替换为 `此页面已删除，剩余 28 天可恢复` + [恢复]。
- 价值流：无数据 `窗口内没有可计算的需求` + [放宽时间窗]；某阶段不适用：列内 `该需求类型不适用`；样本不足：`样本不足（n=3）` 黄 chip，不参与瓶颈。
- 规则：`还没有分支策略` + [新建规则]；核验未启用：黄块 `GitLab 未启用，本次未核验` + [去集成配置]。
- MR：`尚未同步评审信息` + [刷新]；无评论：`MR 还没有行级评论`。
- 代码质量：虚线块 `尚未同步 Sonar 或集成未启用` + [去集成配置]，**不显示 0 / 100% / 绿**。
- 用例评审：`当前版本尚未评审` + [发起评审]；历史为空：`还没有评审记录`。
- 测试数据：`还没有测试数据说明` + [填写]；无附件：`未上传附件`。
- 执行器：`还没有登记执行器` + [新增]；从未上报：`从未上报`。

**错误态**
- 403/404 整页（详情资源不存在一律 404，不用 403 泄露存在性）；列表 5xx 只降级列表，保留筛选与页头。
- 409 一律常驻条（甘特越窗弹窗、阶段最少 2 个、规则重复、评审重复/过期、计划锁定），逐条 `原因 + 修复入口`，不用 toast。
- 外呼失败（核验、MR 刷新）常驻在对应卡内：错误码 + 脱敏原因 + [重试]；不得把整页变错误页。

### 1.6 几何自洽（按最大取值验算，改数必须重算）

| 构件 | 定稿尺寸 | 验算 |

| 甘特整体 `[新增]` | 内容 1192 = 左树 **360** + 时间轴 **832**；行高 40；表头 64（月带 28 + 刻度 36） | 左树：12 + 缩进 48(4 级×16) + chevron 16 + 图标 16 + gap 6 + 编号 64 + gap 8 + 标题 ≥100 + 警示 72 + 12 = **354 ≤360**；300 行 ×40 = 12000，容器内滚 |

### 1.7 反模式（出现即返工）

1. 甘特拖拽乐观改完后**静默回退**：没有 55% 待确认态、没有失败原因、没有审计回执——对应 PRD 反面目标 ①。
2. 用「今天」或创建时间伪造实际条；或画出 FS/SS 依赖线、算关键路径（PRD 明确非目标）。
3. 实际条用饱和色/比计划条更粗，主次颠倒；或计划条被实际条遮住。
4. `UNVERIFIED` 渲染成绿色、计入合规率，或页面只显示一个混合「合规率」——对应反面目标 ②。
5. Wiki 搜索结果显示不可见空间的命中数、片段或「1 条不可见结果」——对应反面目标 ③。
6. 回滚覆盖旧版本、版本号回退、或回滚后旧版正文变化（hash 必须不变）。
7. 用例改版后旧评审仍显示「通过」，或计划页把过期评审当有效背书——对应反面目标 ④。
8. 价值流看板与指标字典/报表两套算法；无审计需求按 0 天或创建时间兜底——对应反面目标 ⑤。
9. Sonar 无快照显示 0 / 100% / 绿色；执行器健康手填。
10. 只靠颜色表意（红/绿点无文字）；或状态 pill 文字宽度随内容跳动。
11. 甘特条内文字溢出被裁（<96 仍塞标题）；外置标签压住下一条。
12. 用 `iframe` 嵌 GitLab/Wiki 编辑器；或在页面渲染时自动外呼 GitLab/Sonar。
13. 阶段配置弹窗里塞 7 组映射（放不下，必然横向滚动）；配置必须是独立页。
14. 用例评审新增第 5/6 类审批单据或在审批中心产生待办（PRD 明确非目标）。

## 2 设计原则

1. **承诺与事实分离**：计划条实心、实际条浅带；没有审计就没有实际期，宁可缺一段，不用今天补。
2. **未核验 ≠ 通过**：三态三色三文字，分母只算已核验；不可达时只允许「备注 + 审计」，不置绿。
3. **无数据 ≠ 0**：价值流、Sonar、执行器一律显式「无数据/未上报」并排除出分母，界面不出现伪造的 0。
4. **版本不可变**：Wiki 回滚生成新版本，评审钉版本；任何「改历史」的入口都不设计。
5. **一处口径一处事实**：同一指标只从服务端同一实现读；同一 MR 事实不在两张卡上各写一份。

- **三视图**：版本（release 行 + 其下需求）、迭代（sprint + 其下任务）、需求（父→子→任务缩进）。视图切换保留域/厂商/版本筛选；切换后回到顶部并滚到今天。
- **缩放**：日 36px/天（周带 + 周末底 `#FAFBFC`）、周 12px/天（周带 `W45`）、月 3.6px/天（`2026-11`）。只改刻度与聚合，不改条的数据口径。

- **键盘**：条聚焦后 `←/→` ±1 天、`Shift+←/→` ±7 天、`Enter` 打开「调整排期」对话框、`Esc` 取消；对话框是**拖拽的等价入口**（无障碍与精确改期）。

## 8 无障碍要点

1. **颜色永不单独表意**：所有 pill/chip 带文字；差异行带 `+`/`−` 前缀；甘特逾期/临期除颜色外有 chip 文案与 `aria-label`。
2. **甘特键盘等价**：条可聚焦（`tabindex=0`，`role=gridcell` + `aria-label="需求 BUS-0001，计划 3月1日至3月8日，临期2天"`）；`←/→` 与 `Shift+←/→` 改期预览，`Enter` 打开「调整排期」对话框提交；杆与行尾菜单都可键盘到达。
3. **焦点**：2px 实心 outline + offset 2px；抽屉打开时焦点移入，关闭后回到触发元素；下钻抽屉与确认弹窗焦点陷阱 + `Esc` 关闭。
4. **对比度**：正文 `#4E5969` 对白 ≥7:1；12px 辅助文字用 `#6b7280`（≥4.8:1）；`#86909c` 只用于 ≥14px 或非信息性文字。
5. **表格语义**：甘特 `role=treegrid` + `aria-rowcount`（含折叠总数）；规则表、执行器表用原生 table；价值流七列用 `<section aria-labelledby>` + 列表，不靠视觉分栏表达结构。
6. **动效**：`prefers-reduced-motion` 下关闭呼吸点、骨架 shimmer、抽屉位移，仅保留显隐；**不自动播放任何数字动画**。
7. **触控命中**：行 40、按钮 32、树 32 均 ≥32；甘特改期热区 8px 在触屏用长按进入「调整排期」对话框。
8. **错误可读**：409/422 以文字 + 错误码呈现（如 `GANTT_OUT_OF_PARENT_WINDOW`），不用图标代替原因。

## 11 设计裁决（不再回问，按此实施）

1. **Wiki 默认可见范围 = 仅本域（DOMAIN）**：空间创建默认 `DOMAIN`，种子空间 `DOMAIN`；跨域共享由负责人显式改为 `INHERIT`。改判影响：仅创建表单默认值与种子 1 行。
2. **用例评审不阻断计划**：`需修改/驳回` 只在用例行、计划页头、执行台标黄提示，不产生 409、不改计划七态。改判影响：计划编辑/执行入口各加一条 409，评审面板文案不变。
3. **不接通用审批引擎**：独立评审单 + `audit_log`，审批中心只增只读 tab，不产生待办。改判影响：新增第 6 类单据与流程种子，UI 不变。
4. **流动效率 =（开发停留 + 测试停留）/（提报→交付）**，仅已交付需求；页面在数值旁常驻该口径（hover 展开），与指标字典同一实现。改判影响：仅公式文案与一个数字，不涉布局。
5. **甘特默认 = 版本 + 月**，从「今天」附近开始滚动；用户上次视图/缩放按人记忆（有记忆时优先）。改判影响：默认值一处。
6. **集成不可达时不允许人工置绿**：只提供「线下核验备注 + 审计」，状态保持 `UNVERIFIED`，页面永远黄 + 「未核验」。改判影响：加一个按钮 + 备注字段，三态语义与 pill 颜色不变（人工结论单独字段，不覆盖 `result`）。
7. **GitLab Token 需 `api` + Maintainer**：权限不足时 `UNVERIFIED`，tooltip 原因写「权限不足（需 Maintainer）」，与「未启用」区分；真实环境不满足时用桩演示，页面不因此变绿。改判影响：仅原因文案枚举。
8. **甘特自绘，不引入 gantt 库**：DOM + CSS + pointer events；理由：审计回执/待确认态/告警 chip 都是定制品，第三方库反而要绕开其状态模型。
9. **MR 评审 = 新增通栏卡**，代码卡保留 `+/-`；同一事实（文件数）只在代码卡计一次，评审卡只用于定位评论，避免两处数字不同步。
10. **阶段配置独立页**（非弹窗）：7 组映射 + 类型 + 排序在 640 弹窗里必然横向滚动；独立页同时满足「保存前预览影响」。
11. **Markdown 前端不解析原始 HTML**：比服务端白名单更严格；正文中的 `<script>` 以纯文本显示。导出/分享若需富文本，走服务端净化。
12. **测试数据锁定 = 全卡只读**：不提供「管理员解锁」入口；确需修改走新计划（避免破坏已完成计划的证据链）。
