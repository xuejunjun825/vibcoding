# 质量管理作业流程差距分析（测试计划 / 测试报告 / 版本质量门）

> 用户要求：测试要有**完整的测试计划管理**；梳理**质量管理缺失的作业流程**；版本发布要有**测试报告的质量门**管理。
> 已实现基线见本轮流水线 PRD：[docs/teamflow/20261108-r2-devops-req-platform/PRD.md](../20261108-r2-devops-req-platform/PRD.md) §4.14（测试计划与执行）、§4.9（发布准入 5 项）、§4.16（指标）。本文件只谈差距与补法，不改已定验收口径。

## 1. 现状（本轮 M5 会交付什么）

- 测试**用例库**：模块树≤3 层、TC 编号、用例版本化、执行记录绑 `case_version`。
- 测试**计划**：挂 Release、选用例集合、执行人、时间窗、状态（草稿/执行中/完成）、四种执行结果、通过率/覆盖率汇总。
- **门禁**：RD「测试通过」按 Release 开关 + 严格/宽松模式。
- **失败转缺陷**：带用例/版本/需求/执行记录。
- **发布准入 5 项**：需求全测过、无未关闭 P0/P1、MR 已填、人天已填、审批已过；PMO 可强制放行。

## 2. 缺口清单（按质量管理的四个作业域）

优先级：**P0**=缺了就「质量门形同虚设」；**P1**=作业流程不完整、靠人盯；**P2**=成熟度提升。

### 2.1 质量策划（把「测什么、谁测、什么时候算完」定清楚）

| # | 缺失流程 | 现状/缺口 | 建议 | 优先级 |
|---|---|---|---|---|
| QP-1 | 版本测试策略/方案 | 只有用例集合，没有版本级测试策略（范围、风险分级、环境、资源、进入/退出条件） | 版本下建「测试策略」文档对象：必测范围（需求清单）、风险点、环境清单、轮次计划、资源；作为测试计划的父级 | P1 |
| QP-2 | 测试计划评审与变更控制 | 计划可直接编辑，无评审、无变更留痕 | 计划加「提交评审 → 批准」两态（可接审批流第五类单据，默认关）；范围/时间/用例增删写 `plan_change_log`（原因、审批人） | P0 |
| QP-3 | 计划准出条件（Exit Criteria）结构化 | 「完成」只等于「无未执行」，通过率/缺陷留存量没有判定口径 | 计划配结构化准出条件：通过率≥阈值、P0/P1 未关闭=0、必需用例集 100% 通过、遗留缺陷豁免清单；不满足时计划不可标「完成」 | P0 |

| # | 缺失流程 | 现状/缺口 | 建议 | 优先级 |

### 2.3 质量保证（结论可签、门禁可执行）

| # | 缺失流程 | 现状/缺口 | 建议 | 优先级 |
|---|---|---|---|---|
| QA-1 | **测试报告**（自动生成 + 版本化 + 签核） | 完全没有。用户明确要求「版本发布要有测试报告的质量门」 | `test_report`：按计划/轮次自动生成（范围快照、用例执行分布、通过率/覆盖率、缺陷统计与趋势、遗留缺陷与豁免清单、风险与结论 PASS/FAIL/CONDITIONAL）；报告版本化、可导出 XLSX/PDF（带水印）、可会签（测试负责人→产品→PMO） | **P0** |
| QA-2 | **版本发布质量门**（Quality Gate） | 准入 5 项里没有「报告」，测试通过是状态而不是可核验的结论 | `quality_gate`：绑 Release/发布单，规则集（测试报告结论=通过且在有效期内、通过率≥X%、P0/P1=0、可选 Sonar 门禁/制品校验）；结果 PASS/FAIL/WAIVED；`quality_gate_snapshot` 固化门禁时刻的数据；发布单准入增加「质量门通过」项 | **P0** |
| QA-3 | 门禁豁免（Waiver）与留痕 | 现在只有「强制放行」一个大按钮，无豁免范围与审批 | `quality_gate_waiver`：规则级豁免（哪条门禁、原因、影响范围、审批人、有效期），发布单展示豁免清单；强制放行降级为「豁免 + PMO 审批」 | P0 |
| QA-4 | 发布评审 Go/No-Go | 只有发布单审批 | 发布评审会视图：质量门结果 + 测试报告 + 遗留缺陷 + 风险清单，一键生成评审记录 | P1 |

### 2.4 质量改进（把结果变成下一轮的依据）

| # | 缺失流程 | 现状/缺口 | 建议 | 优先级 |
|---|---|---|---|---|
| QI-1 | 生产缺陷回流 | 缺陷只能从测试执行或手工提，发布后无回流路径 | 缺陷来源加 `PROD`；发布后观察窗（默认 72h）内产生的缺陷标记为「逃逸缺陷」并回写版本质量门统计 | P1 |

| QI-3 | 质量复盘（根因/逃逸分析） | 无 | 缺陷加根因分类（需求/设计/编码/环境/数据）与发现阶段；按版本出「逃逸分析」报表 | P2 |
| QI-4 | 供应商质量评价 | 无 | 按厂商聚合：一次通过率、缺陷密度、重开率、按时交付率，出厂商质量评分卡（对接管理者视角） | P2 |

## 3. 完整的测试计划管理（对象模型）

```
测试策略(版本) ── 测试计划 ── 轮次 Round ── 执行记录 ── 缺陷
                     │              └── 测试报告 ── 签核 ── 质量门 ── 发布单
                     ├── 计划范围（需求集合 / 用例集合，含 case_version 快照）
                     ├── 执行分配（执行人 × 模块 × 用例数）
                     ├── 准出条件（结构化）
                     └── 变更日志（范围/时间/用例增删 + 原因 + 审批）
```

- **生命周期**：草稿 → 待评审 → 已批准 → 执行中（可多轮次）→ 已完成（准出条件满足）→ 已关闭/归档；任一状态变更写审计。
- **完成判定**：服务端唯一实现——所有轮次里最新状态为准，准出条件不满足返回 409 并列出未满足项；与发布门禁同源，不允许「界面置灰、接口可过」。
- **与发布的关系**：发布单必须挂到某个「已出具测试报告且质量门通过」的版本；报告过期（超有效期/版本内容变更）时门禁自动失效并提示重新出具。

## 4. 版本发布质量门（Quality Gate）设计

- **门禁规则（可配，默认全开）**：
  1. 版本存在**测试报告**，结论 = `PASS`，且在有效期内（默认 7 天，按版本可配）；
  2. 报告结论为 `CONDITIONAL` 时必须有**豁免清单**且经 PMO 审批；
  3. 计划通过率 ≥ 阈值（默认 95%，严格模式=100%）；
  4. 未关闭 P0/P1 缺陷 = 0；
  5. （M6 起可选）Sonar 质量门通过、制品校验通过、最近一次构建成功。
- **门禁执行**：发布单提交时实时计算 + 固化快照（`quality_gate_snapshot`），发布单详情展示每条规则的 PASS/FAIL/WAIVED 与证据链接（报告、缺陷列表、Sonar 链接）。
- **不通过**：409 + 失败项 + 修复指引；仅 PMO/管理员可对**单条规则**豁免，必须填原因、影响范围、有效期，写审计并通知域负责人；豁免记录随单与版本留存。
- **可复算**：任一历史发布单可回看当时的门禁快照与报告版本，数字可由明细复算（不接受只存结论）。

`test_strategy`、`test_plan_round`、`plan_assignment`、`plan_change_log`、`test_env`、`test_report`、`test_report_version`、`report_signoff`、`quality_gate`、`quality_gate_rule`、`quality_gate_snapshot`、`quality_gate_waiver`；

## 6. 验收标准建议（供下一轮 PRD 直接引用）

- **AC-Q1**：测试计划的完整生命周期可走通：草稿→评审→批准→执行→完成→关闭；未批准的计划不能被发布单引用；变更写 `plan_change_log` 且可查。
- **AC-Q2**：计划支持多轮次（R1/R2…），每轮独立记录用例集、执行人、结果与结论；缺陷修复后开新轮次再测，历史轮次不被覆盖。
- **AC-Q3**：准出条件结构化判定——通过率、未关闭 P0/P1、必需用例集三类中任一不满足，计划标记「完成」返回 409 并列出未满足项。
- **AC-Q4**：测试报告可按计划/轮次自动生成，含范围快照、执行分布、通过率/覆盖率、缺陷统计、遗留缺陷与豁免清单、结论；报告版本化、可导出带水印，会签后才能被质量门引用。
- **AC-Q5**：发布单准入含「质量门」项：无报告 / 报告结论非 PASS / 报告过期 / P0/P1 未清 → FAIL 并列出具体规则；绕过前端直接提交同样被拒。
- **AC-Q6**：门禁豁免按规则级生效：必须填原因、影响范围与有效期，PMO 审批后该条转 WAIVED，其余规则仍然生效；豁免与快照随发布单可回看。
- **AC-Q7**：门禁快照可回放——历史发布单能看当时的规则值、报告版本与缺陷清单，数字与明细一致。
- **AC-Q8**：质量指标补齐：一次通过率（FPY）、回归通过率、缺陷逃逸率、发布后 72h 缺陷数、回滚率，均可按域/厂商/版本切片并与看板同源。

## 7. 排期（已定）

缺口中 **P0 有 5 条**（计划评审与变更、准出条件、轮次、测试报告、质量门+豁免），它们是「用户要的测试报告质量门」的直接前置。

**排期决定**：本轮 r2（M1–M5）跑完后，下一个 run 作为 **M6 质量管理补全** 交付本节 P0 五条 + P1 的（测试策略、执行分配与进度、环境台账、Go/No-Go 评审、生产缺陷回流与观察窗）；CI 集成对接（[INTEGRATION-ci.md](INTEGRATION-ci.md)）顺延为 **M7**——两者都碰 `deploy_order.quality_gate_id`，质量门先落地后，集成可直接作为门禁规则接入。
