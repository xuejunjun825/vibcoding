# DESIGN · DevOps 研发管理平台（本轮 M1–M5）

> **基线**：视觉沿用 `docs/teamflow/20261108-r2-devops-platform/UI-STYLE.md` 与其 `prototype/style.css` 令牌（蓝鲸式：200px 侧栏 + 48px 顶部导航 + 白卡片 + `#F5F7FA` 底 + 1px 边框 + 浅底方角 pill）。本文件在其上**扩展 M4/M5**（缺陷 / 用例版本 / 计划执行 / 追溯矩阵 / 开放 API / 门禁），并补齐观感、状态、几何与无障碍规范。
> **冲突裁决**：功能以 `PRD.md` 为准，样式以本文件为准。
> **标记**：`[沿用]` 不改基线；`[新增]` 本轮新页面/组件/令牌；`[修订]` 替换基线并写明原因。
> **技术落点**：`web/`（Vue 3 + Element Plus + Vite + ECharts），仅覆盖 Element Plus CSS 变量 + 一层主题样式；不引入第二套 UI 框架；一期不做暗色主题。

## 1 观感与视觉意图（实现前必读）

### 1.1 一句话
**「安静的企业工作台」**：信息密度中高，层级靠 1px 线与留白建立，不靠阴影与色块；蓝色只出现在三处——可操作、当前项、关键数字。任何页面的任意时刻都必须能回答：**我在哪个租户/域/厂商、这张单处于什么状态、我下一步能做什么**。

### 1.3 状态反馈（**每个可交互元素都必须有，缺一即返工**）

| 元素 | hover | active / pressed | focus-visible | selected | disabled |
| --- | --- | --- | --- | --- | --- |

- 全局过渡：颜色/边框 **120ms**，展开与下划线 **160ms**，抽屉/弹窗/看板重排 **240ms**，缓动统一 `cubic-bezier(.2,0,0,1)`；**禁止** scale 放大、bounce、spring。
- `focus` 不用颜色渐变实现（防止低端屏闪烁），一律 2px 实心 outline。
- 危险操作（删除版本、强制放行、减签、关闭迭代）必须：二次确认弹窗 + 写明影响范围 + 必填原因（如适用）。

### 1.4 动效、加载、空态与错误态

- **抽屉**：右侧滑入 240ms，scrim 160ms（`rgba(31,35,41,.32)`）；Esc 或点 scrim 关闭；有未保存内容时先弹「放弃修改？」。
- **弹窗**：160ms 透明度 + 4px 上移；焦点进入弹窗并锁定（focus trap），Esc 关闭。
- **Toast**：右上角，进入 160ms / 退出 120ms，2s 自动消失，最多堆 3 条；只用于“成功/轻提示”，**不用于错误与门禁拒绝**。
- **加载**：首屏用 8 行骨架（`#F2F3F5` 灰块，shimmer 1.2s 无限，透明度 .45↔.75），不用整页 spinner；翻页保留旧数据 + 顶部 2px 进度条；> 1s 的提交按钮进入 loading 并禁用重复点击。
- **空态**：48px 线性图标 + 一句说明 + 主操作（有权限时）。必须区分两种文案——**“还没有需求”**（引导创建）与 **“当前筛选无结果”**（给「清除筛选」）。
- **错误态**：区域内联卡片（错误码 + 人话 + 「重试」），不弹 toast、不白屏；**409 门禁/状态机拒绝用常驻清单**（§6.1），因为用户需要逐条修复。
- **权限不足**：页面级 403 页（图标 + 「无权访问该单据」+ 返回 + 申请入口说明）；字段级不渲染，或显示 `—` 并 tooltip「无权查看」。**禁止**先渲染再点出 403。
- `prefers-reduced-motion`：关闭 shimmer 与滑入，仅保留即时透明度切换。

### 1.7 反模式（出现即返工）

1. 状态只用颜色区分（必须 pill 文字 + 图标，色弱可辨）；矩阵用纯色块。
2. 把 5 项准入折叠成“一个总状态”，或门禁失败用 toast 一闪而过——用户必须能逐条看到并修复。
3. 门禁未过时按钮直接消失（应保留 + disabled + 原因 tooltip），或“按钮能点、接口 409”两套判定。
4. 权限不足时先渲染再报错；摘要视图不标注来源。
5. 表格行操作常驻显示（应 hover / focus-within 出现）；一屏两个主按钮。
6. 卡片加阴影、边框加粗、圆角 > 8、渐变、插画、emoji 当图标。
7. 聚合数字不可点、点开换了筛选条件（数字与明细对不上）。
8. 用例历史执行显示“最新用例内容”（必须显示当时版本快照并带版本徽标）。

## 2 设计原则

1. **状态即事实**：列表、详情、看板、矩阵、审批时间线共用同一套状态词典与文案（见 §7.3），颜色只是辅助。
2. **权限先于渲染**：不可见的数据不占位；`⚪ 受限` 必须显示范围 chip（本域 / 本厂商 / 本部门）；摘要视图常驻标识。
3. **数字可复算**：每个聚合数字 = 可点开的明细，且**携带当前筛选**；悬停/点击显示指标定义（编码、公式、口径版本）。
4. **门禁常驻**：拒绝原因不消失，直到修复；禁用必带原因。
5. **密度优于装饰**：无阴影、无插画、无渐变；靠 1px 线、对齐与留白分层。

## 8 无障碍要点

1. 对比度：正文 ≥ 4.5:1；12px 文本禁用 `#86909C`；pill 用 §7.2 的 ink 变体；图表文字 ≥ 3:1。
2. 焦点：全部可聚焦元素可见 2px ring；弹窗 focus trap；Esc 关闭浮层；Tab 顺序 = 视觉顺序。
3. 语义：图标按钮必须有 `aria-label`；状态 pill 带文本（不靠色）；矩阵单元 `title` + `aria-label`（“MR：缺口”）。
4. 键盘可达：表格行操作、看板拖拽、加签人员选择均可键盘完成（拖拽提供“移动到…”菜单）。
5. 触控/点击目标 ≥ 32×32（桌面端允许 24×24 的图标按钮但需 32 命中区）。
6. 动效尊重 `prefers-reduced-motion`；无闪烁 > 3 次/秒。
7. 表单：label 与控件 `for/id` 绑定；错误文本 `aria-describedby`；必填星号 + `aria-required`。
