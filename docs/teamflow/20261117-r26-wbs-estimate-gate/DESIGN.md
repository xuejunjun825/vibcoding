## 0. 观感与手感（施工口径，先读）

### 0.1 一句话意图

**一张贴在工作单上的评估回执**：状态是一枚小印章（pill），三个数字（当前人天 / 评估人天 / 偏差）排成一条可核对的横线，下面签着审批人和时间。门没开时，动作行里那枚按钮**留在原地变灰**，旁边一行小字写着为什么——像门闩上挂着的那把锁，看得见、摸得着、推不动。

情绪：安静、可核对、不吓人。全页唯一的"重量"给数字（18px/600 + 等宽数字），颜色只承担状态语义，不承担装饰。

### 0.3 状态反馈

| 状态 | 规格 |
|---|---|
| hover（按钮） | 沿用 `--color-primary-hover` / 默认按钮既有 hover；**禁用按钮 hover 无任何变化** |
| hover（链接） | 文字不变，出现 `text-decoration: underline`（120ms 颜色过渡） |
| focus-visible | 统一 `--focus-ring`（2px 主色）；禁用按钮不可聚焦，提示由可见文本承担 |
| active / pressed | 只做颜色到 `--color-primary-active`，**不做位移/缩放** |
| disabled | 严格沿用 r25：底 `#F2F3F5`、字 `#A9AEB8`、边 `#E5E6EB`、`opacity:1`、无红/黄描边、无阴影、`cursor:not-allowed`；`type` 由 `primary` 降为 `default`；**禁止 `pointer-events:none`**（会杀死 title 气泡）；点击零反馈：无 toast、无抖动、无请求、无 URL 变化、不落 /403 |
| 提交成功后的卡片 | 状态 pill 与数字**就地切换**（无淡入），卡片背景由 `--flash-ok` 经 600ms 线性回到 `--bg-card`，**全页唯一新增动效**；`prefers-reduced-motion: reduce` 时取消闪光 |
| 409（动作被门拦） | 沿用既有 `.action-banner`（危险色，`提交被拒绝：<message>` + code 行），不叠加 toast；同时刷新卡片与动作态 |
| 409（重复提交评估） | 弹窗保持打开，字段下方 12px `--color-danger-ink` 行内错误，不关窗、不 toast |

### 0.4 动效、加载、空态、错误

- **动效预算**：只允许颜色/背景色过渡（`--t-color` 120ms）、弹窗既有 240ms 遮罩、成功后 600ms 卡片闪光。不做位移、缩放、骨架呼吸、数字滚动。
- **加载**：详情为单接口，卡片随详情骨架一起出现，不做局部 loading；若 tech 把 estimate 拆成独立请求，卡片位置渲染 2 行 skeleton（高 16 + 40、`--divider` 底、圆角 4），**不显示"加载中"文字**。
- **空态**：`NONE` **不是空态**——卡片照常出现，pill「未评估」，评估人天/偏差/审批人显示 `—`；禁止用 EmptyState 占位。
- **失败**：estimate 块缺失或接口失败 → 卡片退化为一行 12px「工时评估信息暂不可用 · 重试」，并且**门按 `NONE` 保守禁用**（宁可提前禁用，不可先亮后可点）。
- **弹窗**：打开无自定义动画；提交中按钮 `loading`、两个字段 `disabled`；关闭后焦点回到触发按钮。

### 0.6 几何自洽（按最大取值核算）

- 卡片内容宽 = 容器 − 32。1440 视口下约 1160；四列 `minmax(150,1fr)` + 3×16 = 648，**最窄 700 仍四列**，<720 折 2 列，无横向滚动。
- 最长指标值「1234.5 人天」≈ 8 字 ≈ 80px < 150；偏差最长「+1234.5%」≈ 80px < 150。
- pill 最长 3 汉字（未评估/待审核/已通过/已驳回/已作废/已失效）：3×12 + 16 = 52px，`padding:0 8` 自适应，不设固定宽。
- 标题行高 = max(22, 20, 26) = 26；`flex-wrap:wrap`，<720 时 CTA 换行，卡片高度 +34，指标条不受影响。
- 动作行：右侧最多 5 个 small 按钮（26 高、gap 6），「开始开发」64px 宽，合计约 264px；标题区最小 320，≥960 同行，更窄自动换行（既有 `flex-wrap`）。提示行在其下、右对齐、占满整行，12/18，最长文案约 34 汉字 ≈ 408px < 700，单行；<520 折 2 行（36px）。
- 原因条最多 3 行（3×18 + 16 = 70 高），超出 `-webkit-line-clamp:3` + `title` 给全文。
- 弹窗 520 − 40 = 480 内容宽；人天输入 160；文本域 3 行 = 76 高；底部按钮 26 + 上距 12。
- 卡片整高：26 + 12 + 60（指标条）+ 8 + 18（元信息）+ 8 + 18（门提示）+ 32（padding）≈ 182；无元信息/无门提示时 138。高于右栏「审批进度」卡，视觉上压住首屏是对的。

### 0.7 本产品反模式（明确禁止）

1. 用 `allowedActions` 当这两个动作的渲染开关 → 权限够但按钮消失，正是 r23/r25 反复修的病。
2. 未评估就把「排期/开始开发」藏起来 → 用户不知道被什么挡住。
3. 两类原因混写：权限不足里出现「工时评估」，或门未满足里出现「需要权限」。
4. 给禁用按钮加 `pointer-events:none`、红黄描边、`opacity:.5` 或阴影。
5. 用红色表达「待审核/未评估」——它们不是错误；红色只给驳回。
6. 卡片里出现裸枚举、英文状态、`—` 与「无」混用（空值统一 `—`，门提示里的「无」是状态词）。
7. 为这张卡新增公共组件、新色板、新圆角、渐变或图标库；或改 `StatusPill`/`dict.ts` 的全局字典。
8. 提交成功后再弹一次确认框、再跳一次页面、或整页刷新。

- 空态沿用既有文案，不改；筛选是前端按当前页过滤（既有行为），本轮不改分页语义。

### 3.6 提交工时评估弹窗

```
┌ 提交工时评估 ──────────────────────────────────────── ✕ ┐
│ 评估通过后才能排期或开始开发；通过后人天改动超过 ±20%      │
│ 会自动失效。                                              │
│                                                           │
│ 预估人天 *   [ 10.0 ] 人天                                │
│              0.5 天精度；上次评估 10 人天                  │
│ 说明         [                                           ]│
│              [                                  0/500    ]│
│                                                           │
│                                    [取消]  [提交评估]     │
└───────────────────────────────────────────────────────────┘
```

- 标题：首次「提交工时评估」，重提「重新提交工时评估」；底部按钮文案始终「提交评估」。
- 人天：`el-input-number`，min 0.5、step 0.5、precision 1、宽 160；空/0/非 0.5 倍数 → 字段下 12px 错误，不发请求。
- 说明：3 行、maxlength 500、`show-word-limit`、可选；placeholder「补充评估依据（可选）」。
- 驳回/失效重提时，默认值 = 上一次单据人天（有则填），并在帮助行写「上次评估 10 人天」。
- 409 `ESTIMATE_ALREADY_APPROVED`：不关窗，字段下「该需求已有通过且人天未变的评估单」，刷新卡片；403：行内「无权提交工时评估」，不落 /403。

## 4. 交互与状态

### 4.1 动作行：渲染、禁用、原因的单一算法

```ts
// RequirementDetailView.vue（computed，伪码）
const GATED = {
  schedule:  { type: 'PDR', action: 'req.action.schedule',  label: '排期' },
  start_dev: { type: 'RD',  action: 'req.action.start_dev', label: '开始开发' },
} as const

const estimateStatus = detail.estimate?.status ?? 'NONE'   // 缺失按 NONE 保守处理
const permitted  = canAction(GATED[a].action)              // 动作码判据
const gateOpen   = estimateStatus === 'APPROVED'
const available  = allowedActions.includes(a)              // 接口口径：状态真的允许

const show    = typeMatch && (available || !permitted || !gateOpen)
const enabled = permitted && gateOpen
const reason  = !permitted ? `需要权限：${GATED[a].action}`
              : !gateOpen  ? estimateGateTip(estimateStatus)
              : ''
```

- **为什么不是纯 `allowedActions`**：门未过时接口本就不返回该动作，用它当开关正好把"被门挡住"变成"按钮消失"——PRD §5.7 明确禁止。`allowedActions` 只在"门已通过"的正常分支里确认动作真的可执行。
- **第三类（状态不允许）**：有权限、门已通过、但动作不在 `allowedActions`（如已排期/已开发完）→ **不渲染**，不编造第三套禁用文案；"按钮在但点不动"只用于解释用户可改变的阻塞（权限/门）。
- 权限优先于门：两类原因永不同时出现，因此不会混写。
- 卡片 CTA 同构：`show` 恒真（PDR/RD），`disabled = !can('req:deliver')`，title 为 `需要权限：req:deliver`，`@click` 首行再判一次。

### 4.2 文案单一来源

```ts
// web/src/views/req/estimate.ts（全部 UI 文案从这里取，禁止第二份）
const META = {
  NONE:       { label: '未评估', tone: 'neutral', gateWord: '无' },
  PENDING:    { label: '待审核', tone: 'warning', gateWord: '待审核' },
  APPROVED:   { label: '已通过', tone: 'success', gateWord: '' },
  REJECTED:   { label: '已驳回', tone: 'danger',  gateWord: '已驳回' },
  SUPERSEDED: { label: '已作废', tone: 'neutral', gateWord: '已作废' },
  STALE:      { label: '已失效', tone: 'warning', gateWord: '已失效' },
}
export const estimateGateTip = (s) =>
  `需先通过工时评估（当前评估单：${(META[s] ?? META.NONE).gateWord}）`
```

- 卡片门提示、动作行内联提示、按钮 `title` 三处**同一个函数**，QA 可逐字比对。
- tone 只在本模块内映射到既有 token（`warning` → `--color-warning-bg`/`--color-warning-ink`，`danger` → danger 对，`neutral` → `--bg-hover`/`--text-muted-aa`，`success` → success 对），**不改 `dict.ts` 全局字典**，也不让 `StatusPill` 显示裸枚举。
- 两个禁用原因用不同函数产出：`需要权限：<码>` 与 `estimateGateTip`，物理上不可能互相污染。

### 4.3 点击链路

| 情形 | 渲染 | disabled | title / 内联提示 | 点击后果 |
|---|---|---|---|---|
| 有权限 + 门未过（NONE/PENDING/REJECTED/SUPERSEDED/STALE） | 是 | 是 | `estimateGateTip(status)` | 零请求、零 URL、零 toast |
| 有权限 + 门过 + 动作可用 | 是 | 否 | 无 | 发请求；204/200 后刷新 |
| 无权限（门状态任意） | 是 | 是 | `需要权限：<动作码>` | 零请求、不落 /403 |
| 有权限 + 门过 + 动作不可用（状态不允许） | 否 | — | — | — |
| 卡片提交评估 + 无 `req:deliver` | 是 | 是 | `需要权限：req:deliver` | 零请求 |
| 提交接口 409（已通过且未变） | — | — | 弹窗内行内错误 | 不关窗、刷新卡片 |
| 提交接口 403 | — | — | 弹窗内「无权提交工时评估」 | 就地提示、不落 /403 |

### 4.4 刷新时序（就地，不整页）

1. 弹窗提交成功 → 关闭弹窗 → `emit('changed')` → 父级 `refreshAll()`（详情 + 审批实例 + estimate 实例）。
2. 卡片 pill/数字/门提示/CTA 随新数据重算；动作行 `disabled/title` 同步（PENDING 仍禁用，提示词从「无」变「待审核」）。
3. 卡片闪光 600ms（reduced-motion 取消），**不弹成功 toast**——状态变化本身就是回执。
4. 提交 409 → 保持弹窗 + 行内错误 + 同样刷新；门动作 409（竞态）→ 既有 `actionBanner` + `refreshAll()`，刷新后按钮自动变为禁用态并带门提示。
5. 刷新过程不清空卡片（避免闪烁），用返回数据覆盖。

### 4.5 审批中心过滤

- `BIZ_LABELS` 追加 `WBS_ESTIMATE: '工时评估'`。
- `bizKeyOf(raw)` **最前面**加 `if (String(raw).toUpperCase().includes('WBS_ESTIMATE')) return 'WBS_ESTIMATE'`（`WBS_ESTIMATE` 虽不含 `REQ`，但显式分支防未来规则吞并）。
- 筛选下拉追加 `{ label: '工时评估', value: 'WBS_ESTIMATE' }`，放在「需求」之后；`watch(bizType)` 同步 URL query 的既有逻辑不改。
- 列表行标签、详情摘要、筛选值三者同词「工时评估」。
- **技术前置（非本设计改动）**：详情页 `loadApproval()` 里 `String(row.bizType).toUpperCase().includes('REQ')` 找不到 `WBS_ESTIMATE`，需改为按 `estimate.instanceId` 精确取，或显式匹配 `WBS_ESTIMATE`——否则 AC-6 的"不依赖只看我的待办"不成立。

### 4.6 与 AC-11 的口径边界

`allowedActions` 仍是"接口会不会放行"的唯一真相，本设计**不改变它的内容**（被门挡住的两个动作仍不返回）。前端只在门已通过时用它确认可执行；页面必须**提前禁用**而非依赖 409。若本地门态与服务端不一致（并发改动、夹具过期），以接口 409 返回的 `detail.status` 为准：显示既有 banner + 刷新，刷新后按新 status 重算禁用与文案。

### 4.7 首帧与键盘

- 详情单接口返回前不渲染动作按钮；若 estimate 独立请求，未返回期间按 `NONE` 禁用（保守），返回 `APPROVED` 才放开，避免"先亮后可点"的欺骗。
- Tab 序：卡片「提交评估」→「查看评估单」→ 头部动作按钮。禁用按钮不可聚焦，所以**内联提示必须是真实可见文本**（不是纯 title），否则键盘/读屏用户拿不到原因。
- 提示行 `role="note"`；卡片状态行 `aria-live="polite"`，提交后状态变化可被读出。

## 5. 视觉规范（全部复用，零新增）

| 用途 | 取值 |
|---|---|
| 卡片底 / 边 / 圆角 / 内边距 | `--bg-card` / `--border` / `--r-card` / 16 |

## 6. 无障碍

- **不以颜色单独表意**：pill 有中文词、原因条有句子、门提示有完整文案；色盲用户不丢信息。
- 对比度：提示 12px `#6B7280` 对 `#F7F9FC` ≈ 4.6:1、对白 ≈ 4.8:1，达 AA；驳回/失效原因条 ink 对浅底 ≥ 5.5:1。禁用按钮文字对比度低是 Element 既有事实，但**禁用不是唯一信息通道**——同一原因在提示行以 AA 对比度呈现，故不"修"禁用色。
- `title` 不能作为唯一说明：每个禁用按钮的原因同时是可见文本（卡片门提示 / 动作行提示 / 弹窗帮助），读屏与键盘可达。
- 弹窗：`el-dialog` 既有焦点陷阱；`label` 与控件 `for/id` 关联；错误文本 `aria-describedby`；人天加 `aria-required="true"`。
- 状态更新：卡片状态与门提示区域 `aria-live="polite"`；提交成功不打断当前焦点。
- 动效：`prefers-reduced-motion: reduce` 取消闪光与过渡；无自动播放内容。
- 键盘：禁用按钮不进入 Tab 序是预期；提示行紧随按钮，读屏顺序自然。
