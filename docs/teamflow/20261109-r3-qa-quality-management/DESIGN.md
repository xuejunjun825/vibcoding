## 1 观感与视觉意图（实现前必读）

### 1.1 一句话

**「质检台」而不是「报表站」**：每个质量页面都按同一顺序回答三件事——**结论是什么 → 证据在哪里 → 下一步点什么**。页面底色、字号、1px 线与留白沿用 r2「安静的企业工作台」；质量域只新增两种专属视觉：**结论条**（高 56px，浅语义底 + 左侧 3px 语义竖条）与**证据行**（12px 等宽编号，可点开明细）。红色只出现在 FAIL 与不可逆阻断处，黄色只出现在「需要人判断」处（会签中 / 豁免 / CONDITIONAL），绿色只出现在「已被服务端判定通过」处。

- 全局过渡沿用：颜色/边框 **120ms**，展开/下划线 **160ms**，抽屉/弹窗 **240ms**，缓动 `cubic-bezier(.2,0,0,1)`；**禁止** scale、bounce、spring、数字滚动动画。

### 1.4 动效、加载、空态与错误态

- **状态推进**：计划动作成功后就地刷新结论条 + stepper，150ms 内高亮新当前步（背景 `#EAF1FE` 渐隐 600ms）；不整页跳转、不弹成功弹窗（只 toast）。
- **报告生成**：按钮 loading + 段内 3 步进度（`冻结快照 → 计算 result_digest → 渲染 8 段`），每步 ≤5s；**不遮罩整页**；失败保留页面并给常驻错误卡（错误码 + traceId + 重试）。
- **门禁预评估**：按钮 loading，规则卡原地从“未评估”切到结果；**不重排页面**；固化快照后顶部出现快照条（`#id · hash 前 8 位 · 时间`）。
- **加载**：规则区 5 行骨架；报告纸 3 段灰块（`#F2F3F5`，shimmer 1.2s）；列表首屏 8 行骨架。翻页保留旧数据 + 顶部 2px 进度条。
- **空态**（必须区分“还没有”与“筛选无结果”）：
  - 无策略：`该版本还没有测试策略` + [创建策略]；存量计划显示黄条 `迁移补建 · 范围与风险为空`。
  - 无报告：`该版本还没有会签报告` + [生成报告]（无已批准计划时按钮 disabled + 原因）。
  - 门禁未评估：`质量门尚未评估` + [预评估]；历史发布单：`质量门未启用（历史单据）`，灰条，不伪造 PASS。
  - 无豁免：`没有生效中的豁免` + [申请豁免]；无逃逸：`观察窗内 0 条（截至 11-12 10:00）`——0 是真实值，不回退为 `—`。
  - 指标 null：数字位显示 `—`（20px），下方 12px 说明 `本切片无 R1 执行数据`；**禁止显示 0%**。
- **错误态**：409 一律**常驻清单/结论条**（不用 toast），逐条给 `规则/条件 + 差多少 + 修复入口`；403 整页；404 页面。
- `prefers-reduced-motion`：关闭 shimmer、展开动画与高亮渐隐，仅保留即时显隐。

### 1.7 反模式（出现即返工）

1. 报告只给汇总数、点不开明细；或明细换了一套筛选条件（数字与明细对不上）。
2. 门禁失败用 toast 一闪而过；或页面变红但按钮仍可提交、接口才 409。
3. 保留「强制放行」按钮，或把豁免做成“整门放行”。
4. 用下拉框直接改计划状态；或把会签做成三个并行按钮（越序靠后端兜底）。
5. 计划「完成」失败只弹一句“未满足准出条件”，不列具体用例/缺陷编号。
6. 逃逸数为 0 时显示 `0%`/绿色；无数据与真 0 不区分。
7. 报告打印出现横向溢出、彩色底大面积铺墨、水印只在首页。
8. 一屏两个主按钮；规则卡与证据行常驻显示行操作（应 hover/focus 出现）。
9. 用红/绿纯色块表示门禁结果（必须 pill 文字 + 证据）。
10. 历史发布单/旧报告被新数据改写，或旧单据伪造 PASS。

## 2 设计原则

1. **结论先行**：每页首屏必须先给结论条；结论的每个词都能在下方找到证据。
2. **证据可点**：规则、数字、缺陷/用例清单均可下钻；下钻携带当前 Release/筛选，且服务端同源。
3. **生命周期只走动作按钮**：不提供状态下拉；非法流转不渲染，主流程下一步不可用时 disabled + 原因。
4. **历史只读且不改写**：已签报告、已关闭轮次、门禁快照、评审记录一律只读，用灰底 banner + 锁图标标识。
5. **密度优于装饰**：无阴影、无插画；靠 1px 线、对齐、语义色分层。

## 8 无障碍要点

1. 对比度：正文 ≥4.5:1；12px 禁 `#86909C`；橙/绿/红 pill 用 §7.1 ink 变体；报告纸打印纯黑正文。
2. 状态不靠色：规则/门禁/会签/轮次一律「图标 + 文字 + 颜色」；色弱下仍可读。
3. 键盘：stepper 只读不抢 Tab；轮次 tab 支持方向键；规则卡头 `Enter/Space` 展开；抽屉 focus trap + Esc；复制哈希可键盘触发。
4. 语义：结论条 `role="status" aria-live="polite"`（只在刷新时播报一次）；stepper `aria-current`；会签 `aria-label`；图表提供可读表格。
5. 点击目标 ≥32×32；表格行操作 hover 出现但 `focus-within` 同样可见。
6. 409 清单 `role="alert"`，获得焦点并播报第一项；不自动消失。
7. `prefers-reduced-motion`：关闭 shimmer/展开/高亮；打印隐藏动效。
8. 表单：label `for/id`、错误 `aria-describedby`、必填 `aria-required`；原因计数 `≥10 字` 实时显示。

## 11 设计裁决（不再回问，按此实施）

1. 计划详情用**独立整页 + 6 tab**，不用抽屉承载生命周期（变更/分配/豁免才用抽屉）。
2. 质量门增加**总览列表页**（PRD 只给 `:releaseId`）：否则 PMO 无跨版本豁免审批入口；总览只读，详情才可操作。
3. 报告中心列表页同理为可达性新增；报告正文仍是单页 8 段 + 段锚点。
4. 生命周期**不用状态下拉**；主流程下一步不可用时 disabled + 原因，非法流转不渲染。
5. 会签**严格顺序**：只有当前角色出现签署按钮，越序由服务端兜底但界面不提供入口。
6. 豁免替代强制放行：**P0/P1 规则不出现申请入口**（仅说明硬红线）；历史强制放行记录保留条纹徽标。
7. 工作台为**新建**（代码现状无 `/workbench`），落点优先「我的待执行用例」；数字卡与分组均带 URL 状态。
