## 0. 观感与手感（施工口径，先读）

### 0.1 一句话意图

**把发版这件事，摊成一条看得见因果的四段传送带**：测试 → 三签 → 门 → 准入，四段并排、各自打一枚状态印章，谁没过就停在哪一段；`MISSING` 的段不是空白而是"暂无（原因）"的灰槽——**空不等于通过**。审批链则是一条**逐级亮起的阶梯**：n1 亮，n2/n3 是灰的台阶，不是"待你点的按钮"。

情绪：冷静、可核对、有秩序。全页唯一的重量给**段主值**（18/600 + 等宽数字）；颜色只承担状态语义，不承担装饰；**没有渐变、没有发光、没有大圆角、没有插画**。

### 0.4 动效、加载、空态、错误

- **动效预算**：只允许颜色/背景过渡（`--t-color` 120ms）、既有弹窗 240ms 遮罩、成功提交后的 600ms `--flash-ok` 渐隐。**不做位移、缩放、骨架呼吸、进度条动画、段卡入场动画。** `prefers-reduced-motion:reduce` 下取消闪光——因为其余本来无动画，**实现上不需要第二套样式**。
- **加载**：链路面板 → 4 张 skeleton 段卡（`min-height:132`、底 `--divider`、圆角 4、**不写"加载中"文字**）；审批级别 → 3 行 skeleton（44 高）；快照卡 → 1 行 18 高 skeleton；绑定页 → 卡片区 `v-loading`。
- **空态 / MISSING**：**不是空态，不许用 `EmptyState` 组件**。四段中任一段 `status:"MISSING"` 时该段照常占位，段主值 `—`、印章「暂无」、下方 2 行内 12/18 `--text-muted-aa` 写 `reason`（超出 `-webkit-line-clamp:2`，全文进 `title`）。
- **错误**：链路接口失败 → 面板退化为 1 行 12px「发版链路暂不可用 · 重试」（`--text-muted-aa` + 主色链接），**四段一律不渲染**（宁可什么都不显示，不可显示假 PASS）；绑定页失败 → `ErrorState`（既有组件）整页重试；快照接口失败 → 快照卡保留标题与「重试」，不显示半张快照。
- **首屏竞态**：链路面板与详情同接口（AC-8 一次返回），不产生"先 PASS 后 FAIL"的翻转；**若 tech 拆成二次请求，面板必须先渲染 skeleton，禁止先渲染 `—` 再变状态**。

### 0.6 几何自洽（按最大取值核算，1280×800 为验收视口）

- 侧栏 `--w-sidebar` 200 → 内容区 1080；页面内边距 24×2 → 1032；卡片 padding 16×2 → **链路段区可用 1000**；4 列 + 3×12 gap → **每段 241，段内容宽 217**。
- 段主值最长 `9/9`、`3/3`、`PASS`、`100%`；次行最长 `snap-20261118-000012`（20 字符 × 12px mono ≈ 7.2px/字 = 144）< 217 ✓；`待 PMO 会签`（8 全角 ×12 = 96）✓；失败规则 2 枚 chip（`QG-02 报告未三签` ≈ 130）+ `+2` 24 + gap 4 = 158 < 217 ✓。
- 段卡竖向：padding 16 + 段头 20 + 6 + 主值 26 + 4 + 次行 18 + 4 + 底行 18 + 16 = **128 ≤ 132（`--h-chain-seg`）**，短内容也撑到 132，四段等高。
- 断点：`≥1200` 四列；`1200–960` 2×2（gap 12，段宽 ≈ (952−12)/2 = 470）；`<960` 单列。1280 下**四段全部可见、无横向滚动**（AC-9），首屏竖向占用：页头 ≈96 + 页签 36 + 面板 196 = 328 < 800 ✓。
- 审批级别行：侧栏 320 − 32 = 288 内容；`n1`(32) + 节点名 6 全角(78) + `· 会签`(36) + 印章 52 = 198 ≤ 288 ✓；第二行审批人 `张三、李四、王五`(8 字 ×12 = 96) + `· 11-18 14:02`(≈80) = 176 ✓。
- 绑定槽：3 列 + 2×16 gap → 每槽 (1000−32)/3 = 322，内容 290；定义名最长 `版本发布·常规三级链 v12` ≈ 182 < 290 ✓（单行 `ellipsis` + `title`）；节点 chip 行 `flex-wrap:wrap; row-gap:4`，**最多 2 行（40）**，超出显示前 3 枚 + `+N`（`title` 给全链）；槽高 = 16 + 20 + 4 + 20 + 6 + 40 + 8 + 20 + 16 = **150 ≤ 156** ✓。
- 快照 hash：`#` + 12 hex = 13 字符 × 7.2 ≈ 94 + 复制按钮 16 + gap 4 = 114 < `--w-hash` 132 ✓（完整 64 位只在 `title` 与复制内容里）。
- 弹窗 520 − 40 = 480 内容宽；等级单选 3 枚横排（每枚 ≈120）；紧急原因文本域 3 行 = 76 高；回滚单号输入 260。

### 0.7 本产品反模式（出现即返工）

1. **前端二次判定**：出现 `QG-0`、`REPORT_NOT_SIGNED`、9 项准入顺序常量、或"按签署数推 PASS"的代码（AC-9 静态检索必须 0 命中）。
2. **空段美化**：`MISSING` 段显示成绿色「通过」、或整段隐藏让四段变三段、或返回 `null` 时页面报错。
3. **待办抢跑**：n2/n3 渲染可点「审批」按钮、或显示未到级的待办行；越级入口连"灰按钮"都不给（本就没有该入口）。
4. **快照与实时混排**：同一段位置同时显示两个数字却不标「提交后已变化」，让读者以为是同一个值。
5. **红色当装饰**：给 `待办/进行中/未开始` 用红底；红色只给「未通过 / 被拦」。
6. **在详情页里直接批**：审批只发生在审批中心；详情只做只读展示与跳转。
7. **新造视觉资产**：新增色板、渐变、大圆角、第二套图标、第二套状态字典（`dict.ts` / `StatusPill` 不改）。
8. **等级即时生效**：等级切换无保存按钮、或保存后不刷新链路四段（导致链版本与面板不一致）。
9. **绑定页做危险动作**：提供删除/停用旧单节点定义的入口（AC-4 要求旧定义保留可回绑）。
10. **把 6 个槽塞进表格**：槽内容是多行结构（定义名 + 节点链 + 默认态），表格行会被压成一条，必须用卡片。

## 4. 交互与状态

### 4.0 组件契约（dev/tech 必须一致）

```ts
// FlowChainPanel（纯展示：不判门、不推 PASS、不算 9 项顺序）
props: { chain: FlowChain | null; loading: boolean; error: string }
// FlowSnapshotCard
props: { snapshot: FlowSnapshot | null; history: FlowSnapshotBrief[]; loading: boolean; error: string }
emits: { ('select-round'): [round: number]; retry: [] }
// ApprovalLevelList
props: { levels: ApprovalLevel[]; instanceId?: number; definitionVersion?: number; submittedAt?: string | null }
```
`FlowChain` 四段一律是对象（`status:"MISSING"` + `reason`），**页面不得出现 `chain.qualityGate == null` 分支**。

### 4.1 唯一数据源（前端零判定）

| 展示 | 来源 | 禁止 |
|---|---|---|
| 四段状态/数值/原因 | `flowChain` 一次返回 | 调 gate/report/deploy 二次拼装；按 `levels.filter(approved).length` 推 PASS |
| 审批级别 | `approvalLevels[]`（顺序与长度 = 定义节点序列） | 按 `wf_history` 自行聚合成"级" |
| 快照与差异 | `flowSnapshot` + `changedSinceSubmit`/段级 `stale` | 前端比 JSON / 比 hash |
| 6 槽 | `bindings` 接口（含 `isDefault`） | 前端按名称猜默认 |
| 准入 9 项 | 复用 `GateChecklist mode="admission"`，数据仍取接口（快照态取快照内 items） | 新写 9 项常量/顺序 |

### 4.2 四段显示判定（**唯一一张判定表**）

| 段 `status` | 印章文案 | tone（底/字） | 主值 | 次行 |
|---|---|---|---|---|
| `OK`（全通过） | 已通过 | `--color-success-bg` / `--success-ink` | `3/3`、`9/9`、`PASS` | 摘要（`3 份计划已全部批准`） |
| `IN_PROGRESS` / 有进度未完成 | 待办 / 进行中 | `--color-info-bg` / `--info-ink` | `2/3` | 卡在哪（`待 PMO 签署`） |
| `FAIL` | 未通过 | `--color-danger-bg` / `--danger-ink` | `7/9` | `2 项未通过` + 失败规则 chip（≤2 枚 + `+N`） |
| `MISSING` | 暂无 | 透明底 / `--text-muted-aa` + 虚线边 | `—` | `reason`（2 行 clamp） |

未识别的 `status` 一律按 `MISSING` 渲染（保守：不把未知当成成功）。

### 4.3 等级编辑链路（P3）

1. chip「改」→ 弹窗（当前值预选中，`releaseLevel` 与 `emergencyReason`/`previousDeployOrderCode` 一并提交）。
2. 前端只做"空值/长度"即时提示，**真实判定以 400 `detail.field` 为准**；字段错误落在字段下方 12px `--danger-ink` 行内，弹窗不关。
3. 409 `RELEASE_LOCKED` → 弹窗关闭 + `.action-banner`，并重新拉详情（chip 回真实值，不乐观更新）。
4. 成功 → 关窗、chip 就地换字、`meta-line` 补原因/单号、链路右上的 `v3 链` **不立即改**（等级变更只在下次发起时选链），因此面板不重拉四段——**只重拉详情**。

### 4.4 绑定槽编辑（P1）

| 动作 | 结果 |
|---|---|
| 打开「更换定义」 | 只列同 `bizType`、`PUBLISHED` 定义；列表空 → 弹窗内一行「该类型还没有已发布定义」+ 「去流程定义」链接 |
| 保存 | 成功：该槽就地更新（定义名/节点链/默认态），`ElMessage.success`；**不整页刷新** |
| 400 跨类型 / 未发布 | 弹窗内联错误（`该定义不是 RELEASE 类型` / `定义未发布`），槽不变 |
| 403 | `.action-banner` + 保留当前值；页面顶部出现「只读：需要 workflow:manage」提示条 |
| 恢复默认 | 确认框 → 成功：仅该槽回到默认；「全部恢复默认」同理 6 槽 |

### 4.5 快照回放（P5）

- 默认展示"最新一轮"；下拉选历史轮次 → **在该卡内就地切换**（不做抽屉、不做路由），顶部出现只读条。
- 回放态下所有段/数值/`failedRules` 都取该轮快照，`stale` 印章**不显示**（回放态不谈"变化"）。
- 「返回最新」回到 `current`；若期间有新提交，最新轮次号 +1 并触发 `--flash-ok` 渐隐。
- 快照卡只读：无编辑、无删除、无"重新生成"入口（AC-11）。

### 4.6 提交被拦的三种反馈（发布单）

| 情形 | HTTP / code | 界面 |
|---|---|---|
| 计划未批 | 409 `PLAN_NOT_APPROVED` | `.action-banner`：`测试计划未批准，无法提交` + 第二行 12px 列 `detail.planIds`（各为跳测试计划的链接）；清单与快照不变 |
| 门不过 | 409 `QUALITY_GATE_FAILED` | 复用既有 `.gate-conflict` 块（`snapshotId` + `failedRules` 逐条 code/name/actual/threshold/fixHint + 「去修复」）；快照不生成 |
| 分级字段非法 | 400 `VALIDATION_FAILED` | 若来自发布单提交（回滚单号），字段行内错误 + banner；**详情状态不变** |
| 越级审批 | 403 `FORBIDDEN` | 审批中心 toast + 任务重拉（仍 PENDING），不进详情页 |

**不许**：把 409 变成 toast 一闪而过；把 `failedRules` 折叠进 tooltip；"仍然提交"之类的绕过按钮。

### 4.7 审批中心级别印章（P7）

- 行内（单据列摘要之后）一枚 16 高印章：`第 2/3 级 · PMO 会签`；`mode` 并进节点名（`PMO 会签` 本身即来自后端 `nodeName`，前端不再拼 mode）。
- 任务无级别字段（老实例/其它单据类型）→ 印章整枚不渲染（**不显示"第 ? 级"**）。
- 点击行仍进原详情页；印章不可点。

### 4.8 权限与可见性

| 元素 | 无权限表现 |
|---|---|
| 绑定页「更换定义 / 恢复默认 / 全部恢复默认」 | 渲染、`disabled`、title `需要权限：workflow:manage`、点击零反馈 |
| 等级 chip「改」 | 不渲染（不存在该动作位）；有权限但状态不允许 → 也不渲染，理由由页头 `lock-tag` 承担 |
| 链路段「查看」 | 目标页自身做 403 兜底；本页不过滤（避免"链路缺一格"） |
| 审批中心级别印章 | 与权限无关，恒显示 |

## 6. 无障碍要点

1. **状态不只靠颜色**：每段/每级都有中文状态词（已通过 / 待办 / 未通过 / 暂无 / 未开始 / 已驳回），印章文字即语义；色仅是第二通道。
2. **链路结构语义**：`<ol aria-label="发版链路，共 4 段">`，每段 `<li>` 内 `aria-labelledby` 指向"① 测试计划"；段内数值用 `<span class="sr-only">` 补单位（`3 份中的 3 份`）以免读屏只读"3/3"。
3. **MISSING 必须可读**：`—` 之后紧跟 `reason` 文本，并 `aria-describedby` 关联；**禁止 `aria-hidden` 掉原因的视觉文本**。
4. **级别列表**：`<ol>`，当前级 `aria-current="step"`；「共 3 级 · 定义版本 v3」是列表的 `aria-describedby`。不可批节点不渲染按钮（不是 disabled 的"代批"按钮）。
5. **快照**：`stale` 印章带可见文字「已变化」而非只有黄底；「已变化」段 `aria-describedby` 指向顶部差异摘要；轮次切换后 `aria-live="polite"` 播报「正在查看第 1 轮快照（只读）」。
6. **对比度**：12px 辅助文字一律 `--text-muted-aa`(#6B7280, 4.8:1)；`--text-secondary`(#86909C, 3.0:1) 只用于 ≥14px 或纯装饰；MISSING 虚线边用 `--text-muted-aa`（`--border-strong` 仅 1.6:1，不满足 1.4.11）。
7. **焦点与键盘**：段内链接、等级「改」、绑定槽两个链接、快照轮次下拉均可达；`focus-visible` 统一 `--focus-ring`；弹窗关闭后焦点回到触发元素（Element 默认行为，勿覆盖）。
8. **动效**：唯一新增动效 600ms 背景渐隐；`prefers-reduced-motion:reduce` 下取消。无闪烁、无自动滚动、无自动轮播。
9. **触控/缩放**：200% 缩放时四段折为 2×2，不出现横向滚动（断点按 §0.6）。
