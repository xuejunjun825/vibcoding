与嘉为蓝鲸 DevOps 能力全景图的匹配度评估

评估对象：2026-嘉为蓝鲸DevOps解决方案介绍.pdf（72 页）中的两张纲领图——①「DevOps 产品能力全景图」（需求/开发/测试/部署 × 6 平台 + CAgent + CMeas）；②「研发运营一体化（DevOps）能力成熟度模型」（开发管理 / 持续交付 / 技术运营 三域）。 评估基准：main = 5640227 已交付能力（M0–M6），M7 进行中标注 🔄；证据见 已交付功能模块清单。 判定口径：✅ 自主实现且可验收 · 🔶 部分覆盖（缺关键子项或只做接入侧）· 🔄 本轮进行中 · ⛔ 未覆盖。

1. 结论摘要

视角 匹配度 一句话
需求/协作（CTeam 域） 约 60% 需求全流程、审批、版本、缺陷、任务、迭代、工时、追溯矩阵齐；缺甘特、Wiki、价值流、风险/基线、自动化规则
测试管理（CTest 域） 约 85% 用例库/计划/轮次/执行/报告/门禁/自动化上报齐全，策略与准出结构化是我们比蓝鲸更细的地方
度量分析（CMeas 域） 约 65% 指标字典、看板、报表、测试报告、带水印导出齐；缺多数据源/外部数据集、仪表板拖拽编排
持续集成（CCi 域） 约 45%（M7 后） 触发构建、构建记录、质量门禁、环境台账；流水线编排、代码检查、插件商店靠外部系统
制品管理（CPack 域） 约 35%（M7 后） 检索/选取/sha256/晋级链路；缺制品分发、扫描、依赖目录
持续交付（CCi 部署域） 约 40% 发布单 + 9 项准入 + 上线单 + 执行登记；缺节点/作业编排、脚本库、插件化部署
代码管理（CCode 域） 约 25%（M7 后） MR 结构化、webhook、MR→需求推进；不做仓库托管、分支保护、CR 行级评论
AI 助手（CAgent 域） 0% 明确不做
综合（8 平台等权） 约 44% 强在「需求→测试→质量门→发布准入」主干闭环，弱在「代码/CI/制品的执行面」与「技术运营」

定位判断：我们做的是治理与流水线中枢（需求/审批/隔离/门禁/度量），蓝鲸是工具全家桶。同样是 40–60%，我们覆盖的是"管事"的一半，蓝鲸覆盖的是"干活"的一半。若要继续对齐，性价比最高的是继续用适配层接外部工具，而不是自建代码托管、CI 执行器、制品库本体。

2. 产品能力全景图逐平台对照

2.1 CTeam 敏捷协同（需求域，覆盖 60%）

蓝鲸能力项 我们 对应实现
需求管理 ✅ 三类需求 BUS/PDR/RD、三层父子拆解、需求池、编号规则
任务管理 ✅ 任务挂需求、完成率回写、任务看板拖动持久化
缺陷管理 ✅ P0–P3、状态机+重开计数、执行失败/手工/生产回流三来源
版本管理 ✅ Release + 里程碑、可挂三类需求、延期标红
迭代管理 ✅ 迭代挂 Release、看板、未迁移任务禁关迭代
需求矩阵 ✅ 六环追溯矩阵（需求→任务→MR→执行→缺陷→发布单），缺口实时计算
工时登记 ✅ 0.5h 粒度、周填报、月度锁定、实际人天=工时÷8
需求评审/状态流转 ✅ 差异化状态机 + 自定义审批流（提报/评审入池/版本/发布四类）
规划发布/里程碑 ✅ 见版本管理
甘特图 ⛔ 未交付（PRD §4.22 有设计，无实现）
Wiki / 文档 ⛔ 未交付（PRD §4.21 有设计，无实现）

风险 / 基线 ⛔ 未设计

蓝鲸能力项 我们 说明

安全合规（敏感信息扫描） ⛔ 不做

2.3 CCi 持续集成（开发域，覆盖 45%，M7 中）

蓝鲸能力项 我们 说明

质量门禁 ✅ 我们更强：版本质量门 5 规则 + 报告三签 + 豁免 + 快照可回放；M7 再接 Sonar 门禁

研发商店（插件） ⛔ 不做
编译加速 / 多环境流水线 / 流水线即代码 / AI 排错 ⛔ 不做

蓝鲸能力项 我们 说明

2.5 CTest 测试管理（测试域，覆盖 85%）

蓝鲸能力项 我们 说明
测试计划 ✅ 七态生命周期 + 评审接审批流 + 变更留痕 + 结构化准出条件（比蓝鲸更细）
测试用例 ✅ 模块树≤3 层、TC 编号、用例版本化、执行钉版本
测试执行 ✅ 轮次 R1/R2/R3、执行分配、环境绑定、四种结果
测试报告 ✅ 8 段自动生成、版本化不可变、XLSX(8 sheet)/PDF 带水印、三级会签

2.6 持续交付（部署域，覆盖 40%）

蓝鲸能力项 我们 说明
发布管理 ✅ 发布单 + 9 项准入（服务端计算、409 不可绕）+ 上线单 + 执行登记
节点管理 / 作业管理 ⛔ 不做部署编排（无 agent、无作业引擎）
配置管理 / 脚本管理 / 插件管理 ⛔ 不做
灰度 / 蓝绿 / 回滚 ⛔ 不做编排；仅在指标侧有「回滚率」
发布审批 / 放行留痕 ✅ 审批流 + 质量门豁免 + PMO 强制放行留痕

2.7 CAgent 智能助手（覆盖 0%）

需求生成、任务拆分、用例生成、辅助排错、智能问答——本期明确不做（无模型接入与算力预算，且属体验增强非治理必需）。

5. 我们超出蓝鲸全景图的部分（同期已交付）

  • 域 × 厂商双维度行级隔离：多厂商外包研发的数据隔离，全景图未体现（蓝鲸靠项目/空间模型）。
  • 多租户三形态（ROW/SCHEMA/DATABASE）+ 开通即预设角色与域。
  • 人天成本口径：预估/实际/偏差三级汇总 + 父需求只读汇总（全景图只有"工时核算"）。
  • 二级管理企业提报与集团级需求池双层可见性。
  • 质量门工程化：报告版本+三签+豁免（含硬红线）+ 快照可回放/可 diff + 直连旁路同拒。
  • 字段级脱敏 + 统一作用域谓词（8 个出口同源，含导出/附件/看板）。
  • 测试计划结构化准出条件（409 列 unmet + 修复指引）。

6. 一句话回答

匹配度约 44%（八平台等权），但落在"治理中枢"这一层已经接近 70%：需求全流程、测试管理、质量门与发布准入是我们的强项；代码管理、CI 流水线、制品平台本体、部署编排与 AI 是缺口，且更适合适配集成而非自建。若要继续对齐全景图，建议下一轮就做 甘特图 + Wiki + 价值流 三件（客户可见度最高、纯自建可控），其余靠 M7 适配层扩展。
