# 需求全流程 · 全景演示（配音版）

**时长 6 分 02 秒 · 1440×900 · 30fps · 中文语音旁白（macOS Tingting）+ 底部字幕 · 基线 main `f36467c`。**

与之前几版的区别：

1. **开头先放业务流程图**（`docs/teamflow/diagrams/requirement-flow.png`），旁白讲清 18 个节点、6 个角色、两条异常回退，并把三个阶段按行高亮；
2. **然后按流程图的顺序**逐节点演示：业务方 → 产品经理 → PMO → 研发 → 测试 → 产品经理 → 业务方 → 管理员，共 30 个操作节点；
3. **每个节点都有语音播报 + 字幕**，说明"这一步在流程里的位置、前置条件、被拦时报什么错"；
4. **数据全部来自一次真实的模拟演示**：`make platform-demo-reset` 起干净数据，脚本在真实页面上操作，终态 `BUS CLOSED / PDR ACCEPTED_CLOSED / RD DONE`。

## 复现

```bash
make platform-up && make platform-demo-reset        # 干净演示数据
# Chrome: --headless=new --no-sandbox --remote-debugging-port=9222 --user-data-dir=/tmp/chrome-cdp
node roles/record-roles.mjs                         # 录 30 个节点的前后两帧
node 全景配音版/build-plan.mjs                      # 生成旁白脚本（36 段）
node 全景配音版/tts.mjs                             # 合成语音并测时长
node 全景配音版/render.mjs                          # 渲染字幕帧 + ffmpeg 清单
# 视频 concat + 音频 concat（统一 44.1k mono）→ mux
```

## 已知限制

- 旁白是机器合成音（Tingting，175 字/分）；改文案只改 `build-plan.mjs` 的 `say` 字段后重跑。
- 画面是"截图 + 字幕"的节奏化剪辑，没有鼠标轨迹动画（节点帧保留操作前的高亮框）。
- 拆解子需求、转派厂商、建任务三步为接口落地后拍结果页，其余 27 个节点是页面真点。
