## 业务方（biz1） — 1-业务方-提报与关闭.mp4

| # | 操作节点 | 这一步在流程里的位置 / 前置条件 |
|---|---|---|
| 1 | 进入需求池：只看本业务单元与自己相关的需求 | 域 × 厂商行级隔离：看不到别家厂商承接、也看不到别的业务单元 |
| 2 | 点「提报需求」进入表单 | 业务方只写"要什么、什么时候要"，人天由研发后续评估 |
| 3 | 选类型卡片 / 填标题 / 选业务域 / 选优先级 | 需求类型：业务需求（业务方提报，产品评审后拆解） |
| 4 | 提交 → 状态 SUBMITTED（已提报） | 提交后进入状态机；下一步「提交审批」才真正进审批流 |
| 5 | 提交审批（业务方能做的最后一步） | 业务方只能 submit / withdraw，不能自己批——审批权在产品经理 |
| 6 | 业务方看到汇总人天后关闭业务需求 | 父需求人天/进度只读汇总；关闭是不可逆终态 |

## 产品经理（pm） — 2-产品经理-审批到验收.mp4

| # | 操作节点 | 这一步在流程里的位置 / 前置条件 |
|---|---|---|
| 1 | 审批中心「我的待办」：按单据类型聚合，一条待办=一个节点 | 待办里能直接同意/驳回；驳回必须填原因并进审计 |
| 2 | 同意提报 → APPROVING 结束，需求转「待评审」 | 审批结果通过回调驱动状态机；不是前端改状态 |
| 3 | 发起评审：生成 REQ_REVIEW 评审单 | 评审单是独立实例，评审通过后才允许入池（POOLED） |
| 4 | 评审单待办 → 同意 → 自动入池 POOLED | 评审通过后回调自动 review_pass；入池前不允许拆解 |
| 5 | 拆解产品需求：BUS → PDR（人天由研发后续评估） | 父需求人天只读，由子需求汇总 |
| 6 | 排期：PDR → SCHEDULED（前置：工时评估已通过） | 没过评估门点排期会被 409 ESTIMATE_NOT_APPROVED 拦住 |
| 7 | 拆研发需求：PDR → RD（父 PDR 必须已排期） | 跨类型兄弟不同层：BUS→PDR→RD 三层父子 |
| 8 | 验收通过 → ACCEPTED_CLOSED | 验收后 PDR 关闭；BUS 仍需显式关闭（父需求不会自动关） |

## 项目域负责人/PMO（tl1） — 3-PMO-评估转派与交付.mp4

| # | 操作节点 | 这一步在流程里的位置 / 前置条件 |
|---|---|---|
| 1 | 提交工时评估：PMO/研发提人天，产品经理只审不提 | 没有通过评估单，排期与开始开发都会被 409 ESTIMATE_NOT_APPROVED 拦住 |
| 2 | 转派承接厂商 VEN-A（原因进审计） | 厂商账号此后只能看到本厂商承接的需求 |
| 3 | 交付登记 → DELIVERED（记录交付物与时间） | 交付是"研发说做完了"，验收是"产品说符合预期"，两步分开 |
| 4 | 版本计划与发版审批：版本锁定后才能提交发布单 | 发版链四段（测试计划 → 报告三签 → 质量门 → 准入）由服务端判定 |

## 研发工程师（dev1） — 4-研发-开发到完成.mp4

| # | 操作节点 | 这一步在流程里的位置 / 前置条件 |
|---|---|---|
| 1 | 开始开发 → IN_DEV（前置：RD 工时评估已通过） | 评估单失效（人天改动 >±20%）会被重新拦回 |
| 2 | 任务 TAB：需求拆成任务，DOING → DONE 回写完成率 | 实际人天 = 工时 ÷ 8；任务完成率进父需求进度 |
| 3 | 提交测试 → PENDING_TEST | 提测后测试同学执行用例并给结论；研发不能自证通过 |
| 4 | 合入（merge）→ MERGED | 合入前必须有测试通过结论，PRD 里 MR 链接用于追溯 |
| 5 | 完成（finish）→ DONE，研发侧闭环 | RD 完成后，父 PDR / BUS 的进度与人天自动汇总 |

## 测试工程师（qa1） — 5-测试-计划与结论.mp4

| # | 操作节点 | 这一步在流程里的位置 / 前置条件 |
|---|---|---|
| 1 | 测试计划：挂版本、选用例集合、执行、出报告 | 计划未挂用例按「不满足门禁」处理，不能靠"没测"混过去 |
| 2 | 测试结论「测试通过」→ TEST_PASSED | 失败则一键转缺陷回研发修复，修完重测 |
| 3 | 用例库：用例版本化，执行记录绑定当次版本 | 改用例会产生新版本，历史执行的结论不会"跟着变" |
| 4 | 缺陷列表：测试失败直接转缺陷回研发，修复后重测 | 缺陷与被测需求、用例、执行记录关联，可追溯 |

## 平台管理员（admin） — 6-管理员-权限与治理.mp4

| # | 操作节点 | 这一步在流程里的位置 / 前置条件 |
|---|---|---|
| 1 | 角色与权限：页面 / 动作 / 功能码 三层授权 | 改一个档位，下一次请求立即生效（权限快照 45s + 版本号） |
| 2 | 自动化规则执行日志：命中 / 跳过原因 / 耗时 | 规则只能通知/指派/打标/发 Webhook，不能改状态、不能绕过审批 |
